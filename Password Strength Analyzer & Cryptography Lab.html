1. Password Entropy ($E = L \times \log_2 R$)

Entropy measures the unpredictability of a password in bits. $L$ is the password length and $R$ is the size of the character pool (e.g., 26 lowercase + 26 uppercase + 10 digits + 32 symbols = 94). Every additional bit doubles the number of guesses an attacker must make ($2^E$).

Target: ≥ 75–80 bits for strong security

2. Hashing vs. Encryption

Encryption (e.g., AES-256) is two-way: data is scrambled using a key and can be decrypted back to plaintext. Cryptographic Hashing (e.g., SHA-256) is one-way: it produces a fixed-length mathematical fingerprint that cannot be reversed. Passwords must always be hashed, never encrypted.

One-Way Pre-image Resistance

3. Salting & Rainbow Tables

Without a salt, two users with Password123! share the exact same hash, allowing attackers to crack millions of passwords instantly using precomputed lookup tables (Rainbow Tables). A unique 128-bit random Salt per user forces attackers to crack each hash individually.

Defeats Precomputed Lookup Tables

4. Key Stretching (Argon2id & bcrypt)

General-purpose hashes like SHA-256 are designed to be ultra-fast—modern GPUs can compute billions per second. Password hashing functions like Argon2id, bcrypt, and PBKDF2 intentionally consume CPU time and RAM (memory-hard), slowing attackers down by orders of magnitude.

OWASP Recommended: Argon2id

5. Modern NIST SP 800-63B Password Guidelines

  • Length over arbitrary complexity: Prioritize long passphrases (12–64+ chars) rather than forcing obscure symbol rules that cause predictable substitutions (e.g., P@ssw0rd1).
  • Screen against breached lists: Block known compromised passwords and historical password reuse.
  • No periodic forced expiration: Arbitrary 90-day resets lead to weak incremental passwords (Spring2026 → Summer2026).
  • Allow paste & password managers: Never block pasting into password fields.
